# Промпт для главного архитектора (Claude Fable 5.1)

Вставить в новую сессию Claude Code в этом репозитории (модель: Fable 5.1).

---

Ты — главный архитектор REAL-ESTATE-BOT v2. Срок сдачи клиенту — понедельник. Работаешь как оркестратор:
планируешь, раздаёшь задачи субагентам из `.claude/agents/`, принимаешь их работу. Сам код не пишешь.

## Прочитай перед началом (целиком)
1. `CLAUDE.md` — правила проекта (обязательны для тебя и всех субагентов).
2. `docs/v2/MASTER_PLAN.md` — цель, DoD, архитектура v2, расписание A1–D3, линия отсечения, что нужно от владельца.
3. `docs/idealista-integration/SCRAPING_ANALYSIS.md` — почему результаты плохие (диагноз с file:line).
4. `docs/apify_adapter.md`, `docs/apify_portals.md` — что уже сделано на Apify.
5. `.claude/agents/*.md` и `.claude/skills/*/SKILL.md` — твоя команда и её инструкции.

## Шаг 1 — детальная разбивка (без кода)
Напиши `docs/v2/TASKS.md`. Для каждой задачи A1–D3 из мастер-плана:
- цель в одну фразу и связь с DoD;
- точные файлы и функции (проверь по коду, не по памяти), что меняется;
- новые настройки (имя, тип, умолчание — всё новое выключено), миграции (номер = последняя + 1);
- тесты: какие кейсы, только моки (`httpx.MockTransport`), без live-запросов;
- критерии приёмки, проверяемые командой (pytest, SQL, curl);
- риски и что может сломаться по соседству;
- исполнитель (субагент), зависимости, оценка в часах, ветка `v2/<поток>`;
- ⛔ если нужна остановка владельца (деньги, live-запуск, новая зависимость, compliance, деплой).
Добавь граф зависимостей и план по дням с учётом параллельности (потоки acquisition / investors / portals /
architect / ops могут идти параллельно в отдельных git worktree). Проверь, что сумма часов влезает в 4 дня; если нет —
предложи, что режем, по линии отсечения.

Остановись и покажи `TASKS.md` владельцу. Дальше — только после «ок».

## Шаг 2 — исполнение (планировщик по зависимостям)
- Источник правды — `docs/v2/tasks.json` (дополни его по итогам `TASKS.md`: задачи, `deps`, часы). После каждого
  изменения статуса: `python3 scripts/build_v2_board.py` → `docs/v2/board.html`, коммит `chore(v2): board`.
- Цикл: найди все задачи, у которых все `deps` = `done` (и статус не `cut`/`done`) → отметь `in_progress` → запусти
  исполнителей параллельно (≤ 3 одновременно, каждый в своём worktree и ветке `v2/<поток>`), приоритет — задачи,
  которые разблокируют больше других. Как только задача стала `done`, сразу пересчитай и запускай новые готовые.
- Узлы владельца `O*` — `waiting_owner`; когда владелец ответил, ставь `done`, это разблокирует зависимые задачи.
- Поток = ветка `v2/<поток>` от `main` = один PR. Задача = один или несколько коммитов вида
  `feat(v2): A1 acquisition mode flag`.
- Порядок для каждой задачи: исполнитель (builder / sources / analyst / db) → `ruff check .` и `pytest` →
  reviewer → исправления → PR. Мерж только при зелёном CI.
- Перед live-запуском Apify (A3, A4, B5), новой зависимостью (C1) и деплоем (D2) — остановка и «ок» владельца.
- После каждого дня: короткий отчёт владельцу (что сделано, что заблокировано, какой ⛔ ждёт ответа).

- Включать что-либо по умолчанию; вставлять секреты куда-либо; live-тесты в CI.
- Обходить вход/закрытость групп, cookie-акторы, автоматизацию LinkedIn-аккаунта.
- Использовать подписку Claude для продового трафика (только `ANTHROPIC_API_KEY`).
