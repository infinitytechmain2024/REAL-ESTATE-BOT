## Как снять базовую линию (владелец, на VPS, только чтение)

Делать **до** включения v2-флагов (A1, A3, D2) и повторить после. Команды выполняются в `/opt/real-estate-bot`.

1. Найти кампанию (последние пять):
   ```bash
   docker compose --env-file .env exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select id, left(source_text,60) task, state, created_at from campaigns order by created_at desc limit 5"'
   ```
2. Снять отчёт (скрипт сам включает режим «только чтение» на стороне Postgres, ничего не пишет):
   ```bash
   ./scripts/eval_campaign.sh <campaign-uuid> | tee /tmp/eval-<campaign-uuid>.txt
   ```
3. Из вывода перенести в таблицу выше:
   - блок 1 «Воронка» — число отправленных карточек (`карточек отправлено`);
   - блок 3 «Хосты» — строка «остальные хосты» и список хостов; мусорные считаются вручную по списку `example_url`;
   - блок 4 — `state`/`error_code` порталов (пустой `listings` у упавшего портала = источник не отработал);
   - блок 5 — итог `usd` по `llm` / `api` / `scrape` и общую строку; блок 7 — какие модели платили;
   - блок 6 — лиды (для G6–G9).
4. Открыть отправленные карточки в Telegram и отметить точные (цена, площадь, сделка, регион соответствуют задаче);
   вписать `точных/отправлено`.
5. Дата прогона — `created_at` из блока 0. Файл с выводом сохранить вне репозитория (в нём тексты объявлений и
   контакты); в репозиторий попадают только числа и id кампании.
6. Тот же скрипт после изменения: сравнить строки G\* по числам; рост `$` объяснить блоком 5 («по item»).

Диагностика «почему плохо» — скилл `.claude/skills/diagnose-campaign/SKILL.md`; цены моделей — `docs/v2/MODELS.md`.
