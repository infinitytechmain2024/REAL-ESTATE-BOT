# REAL-ESTATE-BOT v3: мастер-план

Владелец: Dmytro. Архитектор и оркестратор — главная сессия (Fable 5.2). Код пишут и проверяют субагенты на Opus
(`.claude/agents/`), а проверяет всегда другой экземпляр (`reviewer`). Правила — `CLAUDE.md`, после правок
из `docs/v3/RULE_CHANGES.md`. Разбивка задач — `docs/v3/TASKS.md`. Статусы — `docs/v3/tasks.json`. Промпт —
`docs/v3/KICKOFF.md`.

База: `main` @ `7247fb5` (H10, PR #82). Последняя миграция — `050_task_drafts_mode_both.sql`.

## 1. Цель

Бот из одного рабочего места превращается в сервис на 10 пользователей. Что меняется:

1. **Публичное читается через Apify.** Это шесть порталов, сайты клиента (через краулер), открытые группы FB,
   Instagram, TikTok и LinkedIn (только люди и компании). Браузер с входом остаётся запасным путём и нужен для
   закрытых групп FB (D1–D4).
2. **Люди по объекту.** Бот сохраняет всех, кто отметился под объектом: комментарий, реакция или репост. У каждого
   сигнала хранится его сила. Выдача включается настройкой пользователя: кнопка «Кто интересовался», ссылка на пост
   или автоматически вместе с карточкой. Для лида бот готовит черновик первого сообщения, но сам ничего не
   отправляет (D5–D7).
3. **Пользователи.** Остаются две роли: владелец и одобренный пользователь. У каждого свои аккаунты четырёх сетей,
   свои профили браузера и свой прокси. Найденное у каждого своё, хранится 90 дней, `/forget` стирает всё (D8–D13, D20).
4. **Деньги.** Три уровня лимита: потолок на задачу, месячный лимит на пользователя и общий лимит в Apify Console.
   На 80 % бот предупреждает, на 100 % останавливается (D16).
5. **Мини-апп владельца** из четырёх разделов. Настройки меняются и в мини-аппе, и в чате, и это одни и те же
   значения в БД (D14, D15).
6. **Сменный анализ.** Анализ работает либо через ключ API пользователя прямыми вызовами, либо через подписку
   пользователя агентом (Claude Code или Codex в headless-режиме). Агентный режим сначала доступен только владельцу
   (D17–D19).

## 2. Что есть сейчас (сверено с кодом, подробно — `TASKS.md` §0)

- **Сбор.** `ApifyHttp` (`bot/acquisition/apify_client.py:80`) и `ApifyListingSource`
  (`bot/web_search/sources/apify.py:144`) работают. Контракт `AcquiredPost` и `Provenance` рассчитан на Facebook:
  regex id поста (`contracts.py:34`), профиль принимается только с хостов FB (`bot/campaign/leads.py:82`).
  `apify_runs` привязан к пакетам FB (`046_facebook_apify_runs.sql:15`).
- **Соцсети.** Браузерный `bot/social_search/` выключается при `apify` одним местом (`bot/campaign/runner.py:1612`).
  Reach в режиме `apify` продолжает слать `site:`-запросы в SearXNG для LinkedIn и TikTok
  (`bot/campaign/reach.py:168-186`).
- **Люди.** `investor_leads` хранит только комментарии: `comment_text not null`, роль `investor|buyer`, уникальность
  `(profile_key, post_url)` общая на всех (`026_campaign_comment_leads.sql:36`, `:48`). Реакции и репосты не
  собираются нигде.
- **Доступ.** Три роли в БД (`bot/operators.py:22`), владелец берётся из `TELEGRAM_OPERATOR_IDS`. На платформу
  один профиль `<platform>-main` (`bot/control_plane/service.py:527`). Окно входа открывает любой staff, не только
  владелец (`bot/control_plane/live_view.py:174`). Экран зашит размером 1440×1000 (`docker/browser-session.Dockerfile:23`,
  `bot/browser_session/manager.py:78`). Прокси у браузера нет (`manager.py:76-81`).
- **Приватность.** В живом боте нет `/forget`: он есть только в `legacy/bot/handlers/privacy.py:45`. Нет задачи,
  которая удаляла бы лиды через 90 дней: `CAMPAIGN_LEAD_DAYS` только фильтрует чтение (`bot/campaign/settings.py:144`).
- **Деньги.** Бюджет считается только на кампанию (`bot/utils/costs.py:317`). Пользователя можно найти через
  `campaigns.requested_by` (`014_campaigns.sql:10`).
- **LLM.** 14 мест вызова, у каждого этапа свой Protocol (`TASKS.md` §0 п. 14). Ключей пользователей нет.
- **Шифрования нет**, `cryptography` нет в зависимостях.

## 3. Целевая архитектура v3

```
Telegram (чат) ───────────────┐            Мини-апп (владелец: 4 раздела; пользователь: настройки)
  /connect, /login, /settings │            /app/* в telegram:8081 → Caddy; identity = verify_init_data
                              ▼                                   │
              user_settings / accounts / budgets (БД, одни и те же значения) ◄────┘
                              │
     intake (разбор задачи) ── StageRouter (ключ → прямые вызовы | подписка → агент, только владелец)
                              │
        ┌─────────────────────┴───────────────────────────────────────────┐
   СБОР (общий каркас, Apify-first)                         БРАУЗЕР (запасной путь, только чтение)
   порталы ×6 (ApifyListingSource)                          очередь профилей: один браузер, профили по очереди,
   краулер сайтов O2 (ApifyListingSource)                   прокси на профиль, одно окно входа (Mini App
   FB группы/посты/комментарии/реакции                      или одноразовая ссылка на 10 мин), адаптивный экран
   IG, TT: посты + комментаторы                             закрытые группы FB, проверка «вход жив»
   LI: люди и компании (без cookie)
        └─────────────────────┬───────────────────────────────────────────┘
          collected_posts (+platform) · person_signals (owner_user_id, kind, strength) · campaign_costs
                              ▼
     анализ → отбор → дедуп → карточки (кнопка «Кто интересовался») → люди → черновик сообщения (не отправляется)
                              ▼
     бюджет: задача / месяц пользователя (80 % → предупреждение, 100 % → стоп) / Apify Console
     хранение 90 дней · /forget · «Отключить аккаунт» (стирает профиль)
```

Принципы:
- **Один каркас, сменный анализ (D18).** Запуск акторов, `campaign_costs`, бюджет, дедуп, БД и карточки — общие.
  Меняются только этапы «разбор, анализ, отбор, отчёт». Агент получает готовый JSON с собранными данными. У него
  нет `APIFY_TOKEN`, и запускать акторы он не может.
- **Только чтение от имени аккаунта (D7).** Отправка, лайки и вступление в группы делает человек. Это охраняет тест AC-6.
- **Cookie пользователей никогда не уходят в Apify (D1).** В акторы передаются только ссылки и запросы.
- **Прокси только закрепляет адрес (D11).** Подмены отпечатков нет, капча не решается, 2FA не обходится
  (`COMPLIANCE.md` §5).
- **Всё новое за флагом и выключено.** Откат — одна строка `.env` (`docs/v3/ROLLBACK.md`, ведётся с первой задачи).
