## Scrape.do и официальный Idealista API: доказательства

Проверено 2026-10-10. Только публичные первичные источники; без регистрации, обращений в поддержку и платных запросов. Это исследование документации, не подтверждение успешного получения страниц.

### Scrape.do: тарифы и расчёт

[Официальная страница тарифов](https://scrape.do/pricing/): Free — $0, 1 000 credits, 5 concurrent; Hobby — $29/месяц, 250 000 credits, 10 concurrent; Pro — $99, 1 250 000, 50; Business — $249, 3 500 000, 100; Advanced — $699, 10 000 000, 200. Возможности render, residential и geo доступны во всех планах. Лимит останавливает запросы; дополнительный пакет нужно купить отдельно. Цену дополнительного пакета публично не установили.

[Официальные правила расхода](https://scrape.do/documentation/request-costs/): обычный запрос 1 credit; `render=true` 5; `super=true` 10; совместно 25. Для `idealista.*` сервер автоматически включает super: минимум **10 credits**, даже когда клиент этот параметр не передал. При render — 25. За успешные считаются также 400/404/410; не только 2xx. Список специальных доменов не содержит Fotocasa.

Расчёт автора: долларовая доля включённого пакета Hobby = $29 / 250 000 = $0.000116/credit. Это распределённая стоимость, не отдельный pay-as-you-go тариф. Ниже все страницы предполагаются успешными, без других потребителей квоты.

### География, сайты, API

[Geo-targeting docs](https://scrape.do/documentation/proxies/geo-code/): Испания ES есть в datacenter и residential списках; параметр `geoCode=es`. Это подтверждённая возможность географии, не обещание доступности каждого IP в конкретный момент.

[Статья провайдера об Idealista](https://scrape.do/blog/idealista-scraping/), создана 2025-08-05, обновлена 2025-08-06: называет DataDome и показывает получение карточек/поисковой выдачи с `geoCode=es&render=true&super=true`. Поддержка Idealista также подтверждается специальной строкой домена в Request Costs. Успех нашего запроса и участки Мадрида не проверялись. Для **Fotocasa** публичное подтверждение успешной поддержки Scrape.do/DataDome не найдено; считать candidate до smoke/support, а не гарантированной интеграцией.

[Getting Started](https://scrape.do/documentation/): синхронный gateway `https://api.scrape.do/` принимает обязательные query-параметры `token` и `url`; generic `Authorization: Bearer` не документирован. [Async API](https://scrape.do/documentation/async-api/) отдельно использует `https://q.scrape.do` и **X-Token** в заголовке; это другой контракт, не замена auth для текущего GET клиента.

[Output & Response](https://scrape.do/documentation/api-response/response-output/): `Scrape.do-Request-Cost` сообщает фактические credits, `Scrape.do-Remaining-Credits` — остаток. Лимит body 4 MB, для super 2 MB. Стоимость надо извлекать до проверки HTML/status/byte cap: платная успешная у провайдера страница может быть отвергнута нашим парсером.

Рекомендация по коду (не реализовано): расширить существующий `ScrapeApiClient` режимом query token, параметрами geo/render/super, сохранить bearer режим для остальных провайдеров; использовать HTTPX `params` для кодирования; не записывать URL с token, HTTPX exception URL или цепочку исключений с секретом. Добавить передачу billing metadata в costs и предвызовную проверку бюджета по верхней ожидаемой стоимости. Доллары = фактические credits × согласованная ставка пакета; это оценка распределённого расхода, фактический месячный счёт у подписки отдельный. Если header отсутствует, явно обозначать оценку, не нулевой фактический расход.

### Что подтверждено и что предстоит подтвердить

Первичные страницы ниже подтверждают существование каталога, категории или характер источника. Открытие страницы инструментом веб-поиска **не подтверждает** возможность HTTP scraping с IP VPS, разрешение на автоматический сбор, полноту карточек, JSON-LD или прохождение защиты. `Internal Error`, robots и 403 веб-инструмента также не доказывают постоянную блокировку VPS. Поэтому **все маршруты в таблице — предлагаемые**, а не успешно протестированные интеграции. Scrape.do для отдельного домена требует проверки провайдером и ограниченного smoke-теста; обещания универсального unlocker не равны доказательству успеха на этом домене.

`Direct?` означает начать с существующего HTTP-пайплайна и проверить карточки; обычный render допускается только для исполнения JS без stealth/капчи. При отказах — breaker, затем отдельно согласованный внешний провайдер. Для Idealista выбор актора и подтверждения провайдера находятся в `PROVIDERS.md`; официальный API — альтернатива после выдачи доступа. Для остальных сайтов публичный API чтения объявлений этой проверкой не установлен; API публикации/CRM/XML-feed не считается API поиска недвижимости.

### Стоимость: единицы и допущения

- Direct: $0 внешнему scraping-провайдеру; VPS, трафик, поиск, LLM и разработка отдельно.
- Scrape.do: цены таблицы — распределённая доля Hobby, одна оплаченная загрузка на страницу; для неизвестной защиты бюджетируется super–render+super. Дополнительные оплаченные загрузки умножают сумму. Неуспешные запросы по правилам провайдера бесплатны. Общий минимум подписки $29/месяц учитывается один раз, не по каждому порталу. Дешёвые normal/render сценарии приведены выше.
- Apify: 1k/10k **результатов**, не HTML-страниц. Для axly показана ставка карточки; дополнительные billable события и тариф аккаунта требуется проверить. Сопоставление «страница = результат» условное.
- При остановленном fetch внешние расходы $0; дальнейшая direct-проверка также без платы scraping-провайдеру.

Часы — **estimate** одного разработчика на проверку + настройку маршрута + нормализацию карточки + необходимые тесты, поверх существующего worker. Это не измеренные трудозатраты и не фиксированная смета; общую архитектуру, миграцию и клиент провайдера считать один раз, а не 20 раз. Для источников с неизвестным статусом часы обозначают первичную проверку, а не полноценный парсер.

### Предлагаемый порядок

Начать с одного выбранного Idealista actor и существующего HTTP на Terrenos Madrid, Pisos, Yaencontre, Indomio, ThinkSpain, Solvia, Hogaria и Green-Acres. Разблокировку Fotocasa/Milanuncios/SpainHouses включать только после проверки конкретных URL; отсутствие подтверждения успеха сохранять в отчёте, а не маскировать оплаченной попыткой. Sareb предлагается использовать для обнаружения продавца; Haya/Altamira сначала проверить на действующие карточки. Автоматически исключать клиентские порталы по ошибке веб-инструмента нельзя.

Для принятия маршрута записать по нескольким search/card URL: время проверки, IP/окружение, HTTP-код, извлечённые цена/plot_m2/deal/address/URL, billable кредиты/стоимость, число повторов. Проверку с VPS и любые платные вызовы выполнять только в разрешённом владельцем шаге. Изменение `SPAIN_PORTALS`/allowlist на основании этой таблицы — отдельное решение, здесь оно не выполнено.

## Выводы для будущей реализации и проверки бюджета

- Существующий `ScrapeApiClient` (`bot/web_search/scrape_api.py:40`) использует bearer; расширять его, сохраняя старый режим. Сейчас `_scrape` (`worker.py:713`) записывает одну настроенную цену до ответа. Для Scrape.do нужен расход credits из ответа и явная оценка, если metadata отсутствует.
- [Apify Run Actor](https://docs.apify.com/api/v2/actors-runs-post): `maxTotalChargeUsd` ограничивает общую стоимость запуска; API-параметр `maxItems` ограничивает оплачиваемые результаты только соответствующей модели тарифа и не гарантирует размер output. Это отдельно от одноимённого input актора. Для пагинации нужен собственный лимит.
- [Apify Get run](https://docs.apify.com/api/v2/actor-run-get): `usageTotalUsd` — фактическая цена для владельца с авторизацией. Сразу после завершения счёт предварительный; документация рекомендует повторное чтение примерно через 10 секунд. Журналировать и неуспешные запуски; при недоступности цены не записывать «фактически $0».
- Проверка `costs.over_budget()` (`bot/utils/costs.py`) сравнивает уже записанные расходы, без резервирования; при ошибке чтения возвращает False. Это не жёсткая гарантия smoke ≤$1 при параллельных вызовах и неизвестной цене. До smoke нужны согласованные верхние цены, резерв/координация бюджета всех сервисов и provider-side cap. Не расходовать весь $1 на Apify, оставляя analysis/reviewer без бюджета.
- Обработка нового `via="api"` должна менять не только Literal: в `store.finish_fetch` (`store.py:492`) успешным реальным чтением сейчас считается только `via="page"`. При дизайне проверить счётчики, raw payload и последующий analysis, а также повторный захват failed в enqueue и begin_fetch.
- Проверка документа: все 20 доменов из `SPAIN_PORTALS`, ссылки на первичные источники, цены с единицами и оговорками. Полный pytest/Postgres/ruff обязателен после реализации фаз; исследование документации не меняет исполняемый код и не подтверждает прежние 1417 тестов повторным запуском.
