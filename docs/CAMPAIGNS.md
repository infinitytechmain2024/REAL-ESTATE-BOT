# Кампании: инструкция оператора

Кампания — одна цель («что и где искать»), которую бот сам доводит до конца:
находит группы Facebook, читает их окнами по 20 и присылает найденное в чат.
Параллельно она ищет объявления на сайтах (порталы, агентства, классифайды) —
см. [WEB_SEARCH.md](WEB_SEARCH.md).

## Как запустить

- **Текстом:** `/campaign квартиры в аренду в Мадриде` → бот просит
  `confirm <token>` → ответьте ровно этой строкой.
- **Голосом:** в авто-режиме (ниже) авто-оператор просто говорит цель —
  «квартиры в аренду в Мадриде»; бот расшифровывает, показывает текст и ставит
  кампанию. Без авто-режима голос понимает только короткие команды вроде
  «pause everything». Голос — только для операторов и владельцев, с лимитами
  размера и длительности; каждая расшифровка платная (OpenRouter).
- **Авто-режим:** если владелец включил `/auto on`, авто-операторам не нужно
  подтверждение для `/campaign`, `/run`, `/pause`, `/resume`, а обычный текст
  или голос без команды («квартиры в аренду в Мадриде») сразу становится
  кампанией. Бот отвечает «Авто: /campaign поставлена в очередь …». Если цель
  непонятна (нет города или не ясно, что искать), бот объясняет, что уточнить.
- Статус: `/campaign status`. Остановить: `/campaign cancel <id>` (всегда с
  подтверждением).

Города: Мадрид, Барселона, Валенсия, Малага, Аликанте, Севилья, Марбелья, Киев.
Одна кампания — один город. Языки цели: ES/EN/RU/UK.

## Роль пользователя

Владелец одобряет запрос доступа кнопкой **«Approve as user (Пользователь)»**
(или `/role <ID> user`). Пользователь не получает verification, не открывает
браузер и не управляет сбором (`/run`, `/pause`, `/resume`, `/cancel`,
`/login`, `/operators`, `/auto` ему недоступны). Он только даёт задачи:

1. `/start` (или `/mode`) → выбрать режим: «🏡 Участки и объекты» (жильё) или
   «💼 Инвесторы и компании». Выбор запоминается (таблица `user_task_drafts`).
2. Описать задачу текстом или голосом (голос — с теми же лимитами размера и
   длительности), например «квартиры в аренду в Мадриде до 1200 €».
3. Бот интервьюирует, пока задача не описана полностью («grill me»): после
   каждого сообщения (текст или голос) он выделяет всё, что вы сказали, в
   структурированное ТЗ (`TaskSpec`, `bot/campaign/spec.py`) и задаёт ровно
   **один** следующий вопрос — самое важное из недостающих обязательных полей,
   коротко, с 2–4 примерами ответа. Для жилья: место, сделка, тип, бюджет, комнаты
   (для квартиры и дома); для инвесторов: место, кого ищем, тикет, ваша роль
   (ищете деньги или вкладываете). Порядок и примеры — `docs/INTERVIEW_TREE.md`.
   Каждый вопрос идёт с кнопками **«Не важно»** (поле остаётся открытым
   намеренно и больше не спрашивается), **«Хватит, ищи»** (закончить опрос;
   место нужно в любом случае) и **«Отмена»** (удаляет черновик). Ответ можно дать
   одним сообщением на несколько полей. Непонятные или искажённые голосом слова
   бот переспрашивает, а услышанное сообщение показывает один раз: «Я услышал:
   «…»». Опрос ведёт модель `OPENROUTER_INTERVIEW_MODEL` (один запрос на
   сообщение); без ключа или при сбое вопросы задают встроенные правила в том же
   порядке. Не больше `INTERVIEW_MAX_ROUNDS` (10) вопросов, потом показывается
   карточка с тем, что известно. Задача, в которой сразу сказано всё, обходится
   без вопросов.
4. Карточка ТЗ — структурированный список полей (режим, город, районы, сделка,
   тип, бюджет, комнаты, площадь, обязательное, пожелания, исключения, источники,
   выдача; для инвесторов — кого ищем, тикет, роль, география; для владельца ещё
   цель, языки ES/EN/RU/UK и группы окнами по 20) с кнопками **Запустить /
   Изменить / Отмена**. «Изменить» открывает список полей (место, сделка, тип,
   бюджет, комнаты, площадь, районы, пожелания, источники; для инвесторов — кого,
   тикет, роль, география); новое значение поля применяется к ТЗ, остальное не
   сбрасывается, и бот возвращается к карточке. Текст, набранный под карточкой,
   — тоже правка, а не новая задача. Ничего не запускается без «Запустить»;
   повторное нажатие не создаёт вторую кампанию. Авто-режим на пользователей не
   распространяется.

Выбранный режим и город главнее текста: в очередь уходит
`/campaign mode=<real_estate|investors> city=<Город>|place=<имена> spec=<ТЗ> <задача>`,
Orchestra проверяет эти токены (режим — одно из двух значений, город — имя из
списка выше, например `Madrid`, `Málaga`, любое другое место — `place=`) и
передаёт их в `plan_campaign`. `spec=` — подтверждённое ТЗ (URL-safe base64 от
JSON `TaskSpec`): из него `plan_campaign` берёт ограничения (`deal`,
`max_price`, `min_price`, `rooms`, `min_area`, `max_area`, `property_type`,
`districts`) вместо разбора текста, а сам JSON сохраняется в `campaigns.spec`
(миграция 035). Свободный текст цели остаётся для обратной совместимости.
Обычный `/campaign <цель>` оператора по-прежнему определяет всё из текста.
Черновик, не тронутый 24 часа, считается удалённым («Черновик устарел, опишите
задачу заново.»). Когда пользователь нажимает «Запустить», владельцы получают
одну строку: «Пользователь <имя или ID> запустил кампанию: <цель>».

Дальше всё как у оператора: находки и живой статус приходят в чат
пользователя. Пользователю доступны `/campaign status` (только свои кампании)
и `/campaign cancel <id>` (только своя кампания, с подтверждением).
Кампании пользователей расходуют те же общие квоты Facebook
(`SAFETY_MAX_FACEBOOK_*`) и подчиняются тем же предохранителям, что и
кампании операторов; отдельных лимитов на пользователя нет.

## Авто-режим

- `/auto on`, `/auto off`, `/auto status` — только владельцы. Переключатель
  хранится в PostgreSQL (`control_settings`) и переживает перезапуск; пока его
  не трогали, действует `AUTO_MODE` из `.env` (по умолчанию `off`).
- Авто-операторы: владельцы (`TELEGRAM_OPERATOR_IDS`) плюс
  `TELEGRAM_AUTO_OPERATOR_IDS`, и только пока у них есть права оператора.
  Помощник (helper) или посторонний никогда не становится авто-оператором.
- Всегда вручную: `/cancel` (включая `/cancel all` и `/campaign cancel`),
  `/login`, кнопки verification, выпуск профиля из карантина, `/role`,
  `/revoke`, `/operators`.
- В аудите такие команды видны с актором `telegram:<id>:auto`
  (`orchestration_audit_log`), `confirmation_id` у них пустой.

## Что видно в чате

- Одно сообщение статуса на кампанию, оно редактируется по ходу:
  `🎯 real_estate · Madrid · rent` и строка вроде «Сейчас: поиск групп
  Facebook», «Сейчас: Facebook · <группа> · ищу дальше», «Сейчас: анализ»,
  «Пауза: …», «Нужна verification», «Кампания завершена · найдено N».
- Находки приходят по одной, каждая ровно один раз, с хвостом
  «🔎 Найдено: N · ищу дальше». В общий дайджест они не попадают.

## Окна, пауза между ними и лимиты

- Найденные группы читаются окнами по **20** групп; каждое окно — обычный
  Facebook-batch, его запускает `facebook-runner`.
- Между окнами пауза `CAMPAIGN_WINDOW_COOLDOWN_SECONDS` (120 с). Окон не
  больше 10. Одновременно Facebook использует только одна кампания.
- Каждое окно проходит те же квоты и предохранители, что и `/run`, кто бы его
  ни запросил (и в авто-режиме тоже): `SAFETY_MAX_FACEBOOK_BATCHES_PER_DAY`,
  `SAFETY_MAX_FACEBOOK_GROUPS_PER_DAY`, `SAFETY_MAX_RUNS_PER_DAY`, а после
  `SAFETY_BREAKER_CHALLENGES` проверок или `SAFETY_BREAKER_FAILURES` сбоев за
  `SAFETY_BREAKER_WINDOW_HOURS` предохранитель открывается.
- **Дневной лимит Facebook или предохранитель** («daily quota reached …» /
  «safety breaker open …»): новое окно не создаётся, ничего не обходится.
  Кампания не ждёт следующих суток:
  - она дожидается поиска по сайтам, соцсетям и анализа;
  - затем завершается с причиной `facebook_daily_limit` (или
    `facebook_breaker`, если предохранитель открылся ещё до поиска групп);
  - пользователь видит «Поиск завершён.» или «Пока ничего подходящего не
    нашёл.» и строку «Лимит Facebook на сегодня исчерпан, часть групп не
    проверена. Запустите поиск завтра, чтобы проверить остальные.».

  Лимиты задаются в `.env`: `SAFETY_MAX_FACEBOOK_GROUPS_PER_DAY`,
  `SAFETY_MAX_FACEBOOK_BATCHES_PER_DAY`.
- **Выбор групп под лимит** (`next_groups`). Сначала читаются группы, которые
  дали находки за последние 14 дней. Группа, которую любая кампания читала за
  последние 3 дня и которая за 14 дней не дала ни одной находки, пропускается:
  статус `skipped`, причина «no findings in recent reads». Так дневной лимит
  тратится на живые группы.
- **Мёртвые группы.** Группа пропускается всеми кампаниями (статус `skipped`,
  причина «dead: no new posts for 7 days»), если при последнем чтении в ней не
  нашлось постов, или её самый новый пост на `FACEBOOK_GROUP_DEAD_DAYS` (7)
  дней старше этого чтения. Через 30 дней после последнего чтения группа
  читается снова: вдруг ожила. Проверка — один SQL-запрос, тысячи таких групп
  лимит не тратят.

## Контакты из комментариев (для поиска инвесторов)

- Когда бот присылает объект из Facebook, пост встаёт в очередь на одно чтение
  комментариев (`CAMPAIGN_COMMENT_MAX_POSTS` на кампанию).
- Комментарии читаются только когда Facebook свободен (между окнами, после
  поиска), по `CAMPAIGN_COMMENT_READS_PER_ROUND` постов с паузами и не больше
  `SAFETY_MAX_FACEBOOK_COMMENT_READS_PER_DAY` в сутки. Проверка Facebook
  останавливает чтение и считается предохранителем, как и везде.
- Модель (`OPENROUTER_LEADS_MODEL`, без ключа — правила) решает, кто написал:
  инвестор, покупатель, продавец, арендатор или другое. Ответы автора поста
  отбрасываются.
- Инвесторы и покупатели **только сохраняются** (`investor_leads`): имя,
  ссылка на профиль, комментарий, объект, город. Пользователю при поиске
  объектов ничего не приходит, поиск их не ждёт.
- Поиск в режиме «Инвесторы» присылает сохранённых людей своего города (не
  больше `CAMPAIGN_LEAD_PEOPLE_MAX`, за `CAMPAIGN_LEAD_DAYS` дней), каждого
  один раз: профиль, контакт, если он есть в комментарии, превью (сколько
  объектов, какие, цены, когда), рекомендация, как связаться, и все его
  комментарии со ссылками на объекты.
- Бот только читает: ничего не пишет, не лайкает, никому не отправляет
  сообщения. Выключить: `CAMPAIGN_COMMENT_LEADS=off`.

## Где искать: любое место мира

Фиксированного списка городов и стран нет. Место — любой город, район,
остров или регион мира («Убуд, Бали», «Дубай Марина», «Лиссабон»):

- ИИ разбора задачи возвращает место на английском, его названия на es/ru/uk,
  падежные формы («Убуде») и страну (ISO-2). Язык задачи место не задаёт:
  украинский текст не значит «Киев». Если места нет, бот спрашивает, кнопок
  с городами больше нет, место пишется словами.
- Без ключа ИИ бот узнаёт известные названия (Мадрид, Барселона, Киев …) по
  встроенному словарю написаний, а любое другое место берёт так, как его
  написали в ответе на вопрос «В каком городе искать?».
- В очередь место уходит токеном `place=` (названия и страна) или
  `city=Ubud,_Bali` (пробелы через `_`) — так можно запускать и `/campaign`.
- Порталы недвижимости (Idealista и т. п.) используются только для Испании и
  Украины; в других странах — открытый поиск, группы, соцсети и охват.

## Охват площадок (поиск инвесторов)

Поиск в режиме «Инвесторы» (и смешанный) параллельно ищет инвесторов,
агентов, агентства, фонды, клубы бизнес-ангелов и девелоперов **на всех
площадках** через поисковики (внутренний SearXNG: Google, Bing, DuckDuckGo,
Brave …), по одной площадке за запрос:

| Площадка | Пример запроса |
|---|---|
| LinkedIn (люди, компании, посты) | `site:linkedin.com/in "real estate investor" Madrid` |
| Reddit | `site:reddit.com real estate investing Madrid Spain` |
| X (Twitter) | `site:x.com inversor inmobiliario Madrid` |
| Telegram (публичные каналы) | `site:t.me управление виллами Убуд` |
| Instagram, TikTok, YouTube | `site:instagram.com agente inmobiliario Madrid` |
| Сайты | `red de business angels Madrid`, `"family office" inversión inmobiliaria Madrid` |

- Запросы сначала пишет модель по самой задаче: кого ищут, где, на каком
  языке («русскоязычные компании по управлению виллами, Убуд» → русские и
  английские запросы по Telegram, Instagram, LinkedIn, сайтам),
  `INVESTOR_REACH_MODEL_QUERIES` (10) штук; остальное — шаблоны (испанские
  только для Испании).
- Читается только выдача поисковика: ссылка, заголовок, фрагмент. Сами
  площадки бот не открывает, в аккаунты не входит, ничего не пишет.
- Модель (`OPENROUTER_REACH_MODEL`, без ключа — правила по словам) решает, кто
  это (инвестор, компания нужного вида, агент, агентство, фонд, клуб,
  девелопер, «ищет инвестора», другое), подходит ли под задачу и работает ли
  он в этом месте. Каждая ссылка оценивается один раз
  навсегда (`reach_contacts`).
- Подходящие приходят карточками: кто, площадка, ссылка, кратко, контакт из
  фрагмента, рекомендация. Сначала люди из комментариев под объектами, потом
  найденные на площадках; всего не больше `CAMPAIGN_LEAD_PEOPLE_MAX` (60) на
  поиск, каждый один раз. Следующий поиск инвесторов в том же городе пришлёт
  и тех, кого нашли раньше, но ещё не присылали ему.
- Лимиты: `INVESTOR_REACH_QUERIES_PER_CAMPAIGN` (16) запросов на поиск,
  `INVESTOR_REACH_QUERIES_PER_DAY` (80) в сутки. Поиск завершается после
  охвата (не дольше `CAMPAIGN_SOCIAL_GRACE_SECONDS`). Выключить:
  `INVESTOR_REACH_ENABLED=false`.

## Verification (проверка Facebook)

Если Facebook показал проверку, окно останавливается, кампания получает
статус «Нужна verification», операторам приходит сообщение с кнопкой.

1. Кнопка открывает Mini App в Telegram (или скопируйте ссылку в Safari).
2. **Claim** — берёте задачу себе.
3. **Open live browser** — браузер профиля; решите проверку руками.
4. **Solved** — бот проверяет страницу.
5. **Resume the run** — окно продолжается с той же группы, кампания идёт дальше.

Пароли и коды вводятся только в браузере сервера; бот их не видит.

## Что всегда делает человек

- **Первый вход** в Facebook-профиль: `/login facebook facebook-main` в личном
  чате с ботом (или `bash scripts/browser_login.sh facebook facebook-main`).
- **Проверки (checkpoint/CAPTCHA)** — через кнопку verification выше.
- **Карантин:** проверка личности, новая 2FA или ограничение аккаунта —
  профиль уходит в карантин, владелец получает одноразовую ссылку. Вернуть
  профиль в работу можно только вручную: владелец разбирается с аккаунтом и
  заново входит через `/login`.

## Настройки `.env`

| Ключ | Смысл |
|---|---|
| `AUTO_MODE` | `on`/`off`, по умолчанию `off`; `/auto` меняет его во время работы |
| `TELEGRAM_AUTO_OPERATOR_IDS` | числовые ID одобренных операторов, кроме владельцев |
| `CAMPAIGN_POLL_SECONDS` | как часто runner проверяет кампании (10) |
| `CAMPAIGN_WINDOW_COOLDOWN_SECONDS` | пауза между окнами (120) |
| `CAMPAIGN_ANALYSIS_GRACE_SECONDS` | сколько ждать анализ после последнего окна (600) |
| `CAMPAIGN_REFUSAL_RETRY_SECONDS` | повтор после отказа квоты/предохранителя (300) |
| `SAFETY_*` | квоты и предохранители, общие для `/run` и кампаний |
| `CAMPAIGN_COMMENT_LEADS` | чтение комментариев под объектами: `all`/`investors`/`off` (`all`) |
| `SAFETY_MAX_FACEBOOK_COMMENT_READS_PER_DAY` | постов с комментариями в сутки (40) |
| `CAMPAIGN_LEAD_PEOPLE_MAX`, `CAMPAIGN_LEAD_DAYS` | сколько людей и за сколько дней присылает поиск инвесторов (30, 90) |
| `FACEBOOK_GROUP_DEAD_DAYS` | через сколько дней без новых постов группа считается мёртвой (7) |

```sh
git pull --ff-only
./scripts/apply_migrations.sh
docker compose --env-file .env up -d --build
```
