# real-estate-pipeline

Скилл для работы в этом репозитории. Цель бота: по задаче из Telegram найти **все**
подходящие объекты недвижимости (или инвесторов) на обязательных сайтах, проверить каждую
находку по критериям и отдать пользователю только то, что прошло, с объяснением остального.

## Перед началом любой задачи

1. Прочитай `PLAN.md` (чек-лист) и `docs/REVIEW_AND_PLAN.md` (почему так). Найди задачу
   по номеру (`0.2`, `1.3` …). Если пользователь не назвал номер — предложи ближайшую
   незакрытую задачу текущего этапа; этапы идут строго по порядку.
2. Прочитай файлы, указанные в задаче, **целиком**. Ключевые места:
   - intake и вопросы: `bot/control_plane/intake.py`, `understanding.py`
   - план кампании: `bot/campaign/architect.py`, `models.py`, `geo.py`
   - веб-поиск: `bot/web_search/{queries,worker,fetcher,store,urls,structured,render}.py`
   - фильтр и карточки: `bot/campaign/{tolerance,relevance,runner}.py`, `bot/analysis_pipeline/`
   - агенты: `bot/agents/{extraction,jev,gate,reduction,recorder}.py`
   - инвесторы: `bot/campaign/{reach,leads}.py`
   - миграции: `bot/services/db/migrations/` (нумерация сквозная, следующая — 031)
3. Проверь, нет ли уже теста на это поведение в `tests/` — расширяй его, а не дублируй.

## Четыре роли при выполнении задачи

Выполняй каждую нетривиальную задачу этими шагами. Для крупной задачи запускай роли
как субагентов (Agent tool); для мелкой — проходи роли сам, но письменно.

### 1. Архитектор (сильная модель)
- Переформулируй задачу из PLAN.md в список конкретных правок: файл → функция → что меняется.
- Назови hard-критерии готовности (из поля «Проверка» в PLAN.md) и риски: что может сломать
  соседний этап (Facebook-окна, квоты, outbox Recorder, идемпотентность).
- Если задача требует решения пользователя (платный API, прокси-провайдер, модель) —
  остановись и спроси **до** кода.

### 2. Сборщик (быстрая модель)
- Вноси правки минимально и локально. Не трогай лимиты безопасности Facebook
  (`SAFETY_*`), verification, outbox и миграции прошлого — только новые миграции.
- Новая настройка = поле в соответствующем `settings.py` + строка в `.env.example`
  с комментарием + строка в docs.
- Каждая правка сопровождается тестом в `tests/`. Для SQL — тест на реальном Postgres
  (см. `tests/test_campaign_postgres.py`).

### 3. Рецензент (сильная модель)
Прогони чек-лист и выпиши нарушения с file:line:
- [ ] Запросы содержат тип, сделку, цену, комнаты, город **и страну**? (`queries.py`)
- [ ] Город не расширяется до региона без `place_level`? (`geo.py`)
- [ ] Нет fail-open: неизвестное по hard-критерию ≠ `exact`? (`tolerance.py`, `runner.py`)
- [ ] 403 ведёт на следующий слой, а не в блок на 12 ч? (`store.py`, `worker.py`)
- [ ] Лимит хранится в БД, не в памяти процесса?
- [ ] Один объект на нескольких сайтах → одна карточка?
- [ ] Ничего из найденного не исчезает молча: у каждой отброшенной находки есть причина
  в `agent_findings`/`campaign_findings`?
- [ ] Промпты не просят модель «не спрашивать» и не выдумывать факты; у фактов есть цитата?
- [ ] Миграция добавляет, а не меняет применённую? CHECK-ограничения синхронны с кодом?
- [ ] `make lint test` зелёный; golden-тест этапа проходит?

### 4. Финалист
- Сверь результат с критерием «Проверка» задачи и с «Критериями приёмки» в конце PLAN.md.
- Отметь задачу `[x]` в PLAN.md, допиши строку в `docs/RESULTS.md`, если менялась выдача.
- Коммит: `<этап.задача>: <что сделано>` + тело «зачем», без упоминания моделей-исполнителей.

## Инварианты проекта (не нарушать)

- Бот только читает: ни лайков, ни сообщений, ни авто-обхода капчи. Verification — человеком.
- Facebook: окна ≤ 20 групп, квоты `SAFETY_*`, одна кампания на Facebook одновременно.
- Каждая находка один раз через Recorder-outbox; повторная доставка ничего не дублирует.
- Секреты не логируются; прокси и ключи только из env.
- Карточки пользователю — на русском; промпты — на английском; запросы — es/en/ru/uk.

## Золотой тест

`tests/golden/valencia_200k.json`: задача «квартира в Валенсии до 200 000 €, от 2 комнат,
покупка». Ожидания: `task_kind == apartment`, в запросах есть `200000|200.000`, `2 habitaciones`,
`Valencia` + `España|Spain`, порталы первого раунда — idealista, fotocasa, habitaclia, pisos.
Запуск: `pytest tests/golden -q`. Прогоняй после каждой задачи этапов 0–1.

## Как расширять список обязательных сайтов

1. Добавь хост в `SPAIN_PORTALS` (или свой список страны) в `bot/web_search/urls.py`
   и regex `listing`/`index` в `PORTALS`.
2. Прогони `python scripts/portal_probe.py https://<сайт>/<страница объявления>` с VPS,
   запиши слой в `docs/PORTALS.md`.
3. Если сайт отдаёт 403 на всех слоях — не блокируй навсегда: оставь сниппет-карточку
   с пометкой «не проверено» и причину в финальном отчёте.
