# add-llm-stage

1. Модель — только через переменную (`OPENROUTER_<ЭТАП>_MODEL`, позже общий клиент `LLM_PROVIDER`). Не хардкодить.
   Выбор: массовая классификация — Haiku/Sonnet; разбор задачи и отчёт — Opus. Цены — `docs/v2/MODELS.md`.
2. Ответ — строгий JSON по схеме (pydantic), образец `bot/analysis_pipeline/openrouter.py` и
   `bot/control_plane/understanding.py` (json_schema → json_object при 400, нормализация перед валидацией).
3. Каждое число и вывод — с цитатой из исходного текста; число без цитаты отбрасывается (`verify_facts`).
4. Ошибки с кодами (`ai_failed`, `schema_mismatch`, `model_unavailable`), без тихой потери; 401/402 — остановка пакета.
5. Стоимость каждого вызова — `costs.record("llm", …, campaign_id=…)`; проверка `costs.over_budget` до вызова.
6. Fallback: при ошибке/таймауте — детерминированные правила или предыдущий провайдер, пользователь не теряет задачу.
7. Тесты: мок ответа (валидный, вне схемы, 400, таймаут), учёт стоимости, отсутствие ключа в логах.
